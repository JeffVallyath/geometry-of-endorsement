# Pre-outcome interpretation and runtime rules

The supplied PROTOCOL.md is authoritative. All 64 final case IDs stay in the
primary denominator (18 targets for each stored seed). Ineligible, invalid and
null outcomes are not deleted. The case is the independent unit.

Gates, matched pairs, three withheld questions per format, validator inputs and
hash tie-breakers are fixed in generated/*/PLAN.json. Full prompt/token records
are fixed in PROMPTS.json.gz. One selected structural pair applies to both seeds
because the learned methods preserve the exact same source text; execution must
verify its actual prefix IDs against the freeze. There is no lexical or clause-
position matching claim.

Primary rates average seeds within each case; 10,000 paired case bootstrap draws
use seed 2609182102 and 95% percentile intervals. Both-code sensitivity counts
nine semantic targets per case per seed and requires one common pair and the
same semantic direction, not two independently found disagreements.

For utility, freeze the two procedures' decisions AND all equal-retention
rankings before any full-battery primary analysis or withheld-outcome analysis.
Each isolated procedure receives only its exact common direct checks plus six
validation response IDs. The isolated decision process receives only an allowlisted input packet
and cannot read the remaining study records.
It additionally refuses filesystem/network access after stdlib initialization.
Common direct reads cost 24 scores per case/seed/format: six at each selected
history, six native and six no-op. These selected histories have nonzero equal
changed-fact counts, so no-op is a distinct history. Record suffix/prefill costs
separately; equality in query count is not equality in GPU cost.

The named utility contrast is B minus A task-error fraction at 50% retained,
computed independently for each seed then averaged equally. Reapply eligibility
and ranking in each paired bootstrap sample, using the same case hash for ties.
Any undefined bootstrap draw makes its interval unavailable. Literal No/Yes is
primary; A/B is sensitivity. Fewer than 20 distinct common cases per seed rules
out a quantitative utility headline. Report acceptance, accepted errors,
accepted successes, both asymmetric acceptance sets, and 25/50/75% retention.
Intervals are descriptive, not a second confirmatory success gate. A negative
named contrast is directional utility evidence, qualified by uncertainty and
seed/interface results; rejecting more cases alone is not evidence of utility.

Fresh confirmation means qualifying fresh witnesses were observed under the
full frozen criterion, with repeat coverage/discrepancies reported. It does not
imply utility. A complete zero is a fixed-test null, not a technical failure.

The original SSC1 core-to-fresh-pass numerical rule is preserved for the two
old replay cases and the final fresh-process repeats: same hard choice,
validity and token binding, max absolute log-probability difference <=1e-6.
The retained saved-score implementation is `source/panels.py`,
function `compare`.
The unrelated older RSO3 anchor's 0.05 cap is NOT substituted. Every score
discrepancy (including nonzero differences below tolerance) is retained.

GPU runtime: Python 3.12.3, Torch 2.11.0+cu128, Transformers 4.56.2, NumPy 2.2.6,
CUDA 12.8 and cuDNN 91900, with original BF16/FP32 semantics. The known inherited
CPU package pins and the official Torch wheel's exact GPU dependencies form a
hash-locked Linux resolution. No fresh scientific outcome can trigger a runtime
or numerical amendment. Only deterministic binding repairs may be considered,
with failed attempts retained and the readout/time/cost ceilings unchanged.
