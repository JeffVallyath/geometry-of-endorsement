# Privacy boundary and historical audit

The review was performed on a private team snapshot before its publication.
This is an attributed repository, not an anonymous release. Authorship,
licenses, public repository links and dataset entity names remain intentional.
History counts below describe that private multi-ref checkout at review time,
not the public branch. Publishing the current files does not merge private
Git history into the public branch.

## Current files and original custody

The current tree was inspected as actual files, including newly imported
evidence, compressed JSON/text, NumPy string arrays, notebooks and their
outputs/metadata, Parquet string columns, and image/PDF metadata. The targeted
credential patterns produced no hits. That is not a guarantee against every
possible secret encoding or personal disclosure.

Machine-local user attachment/interpreter paths, the fresh-study model-cache
location and operational links in the dated audit were removed in documented
derivatives. Scientific values, raw scores, labels, gates, model revisions and
original archive identities were preserved. The released ValuePrism status was
narrowed to its disposition and missing runtime component; ownership, clocks
and continuation instructions are outside the current evidence selection.

[privacy_derivatives.json](../reproducibility/privacy_derivatives.json) gives
distinct original and derivative hashes, sizes and exact field-level changes.
Original bytes are preserved in an external content-addressed private store.
Compact manifests honestly bind the new derivative bytes; they do not claim
modified files still have their old hashes. Old integration reports and diffs
are preserved externally. A [dated integration summary](history/READABILITY_INTEGRATION_20260919.md)
replaces the root workflow report.

Historical generic worker paths and fixed project-local defaults inside original
execution source are retained as provenance. They do not identify a personal
home or authorize execution. Current replay commands use explicit portable
paths and block model/network access. Detailed matched text and author-identity
inventories are outside this repository so this report does not repeat them.

## Available Git history

The scan covered 28 available refs, 73 commit objects, four annotated tags and
3,896 unique historical blobs, including deleted-file versions. Commit/tag
messages and author/committer/tagger fields were included. No matched credential
pattern was found. Historical user-local paths and operational workflow prose
remain in those Git objects even after the current-file cleanup.

First-person prose matches in historical dataset and reviewer CSVs were retained
as supplied example text, not classified as the author's autobiography.

The 147 objects reachable only from the two active study branches were excluded
to preserve sealed outcomes. No remote-only refs, unreachable/reflog-only objects,
external forks, provider storage or copies outside the supplied workspace are
claimed scanned. Current-tree deletion is not history cleanup.

   and the original private archives before changing any history.
2. Review the external hit inventory and define an exact path/blob/message
   replacement map. Keep scientific source hashes, legitimate attribution and
   the sealed-study boundary explicit.
3. Apply the reviewed map to an isolated copy using a supported history-rewrite
   tool. Rescan every authorized ref and compare all scientific evidence with
   the preserved originals.
4. Coordinate any replacement remote and collaborator recovery before a push.
   Decide separately how to retire old remote objects, clones and caches.

The audit did not rewrite history, force-push, rotate credentials or operate
live studies. Its history-cleanup plan remains unexecuted.
